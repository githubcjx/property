净值目标 · 交互说明

V2.0 P0-2 · 改造 pages/milestones 为「净值目标」 · 新增 goals 集合 + services/goal.js
1命名与位置

页面名定为 「净值目标」（4 字），和工具面板里已有的「净值趋势」成对，同时涵盖「我自己的目标」与「7 个预设关口」。工具格子标签由「里程碑」改为「净值目标」，data-url 仍指向 /pages/milestones/milestones（不改路由，省一次全局替换；页面内标题与导航栏文案改掉即可）。备选：净值关口 / 我的目标 / 目标进度。

2一期只支持一个进行中的目标

多目标会立刻引出「哪些账户算进这个目标」，那是另一个产品。一期的产品表述保持干净：我的下一个目标是什么、还差多少、照现在的速度什么时候到。goals 集合按 isArchived 过滤，同时只允许一条 active；换目标 = 归档旧的、建新的（旧目标不删，为二期的「目标历史」留数据）。

3目标卡（主态，见 ① 号机）

自上而下：目标名 + 编辑按钮 → 完成度大数字（比金额更适合当主视觉，且天然规避打码问题）→ 进度条 → 当前 / 还差 → 预计达成月份 → 口径说明小字。金额受全局 hideAmount 打码，百分比和预计日期不打码（不含绝对金额，且是这张卡的意义所在）。

4设定目标（见 ② 号机，可点击）

半屏面板：常见目标快捷 chip（应急金 ¥10 万 / 首付 ¥60 万 / 一百万 / 自定义）→ 名称输入（≤10 字）→ 金额键盘（带 000 键，目标金额通常是整数万）。点 chip 自动带出名称与金额，仍可改。保存后空态卡就地替换为主态卡。金额按本位币存储并记录币种——若存人民币分，本位币是美元的用户会看到目标随汇率漂移。

5预测口径与四种降级（见 ③ 号机）

预测 = 剩余金额 ÷ 月均净增，只用用户自己的真实历史外推，不提供自填收益率——这是与 Kubera Fast Forward 的分界线，也是不变量 10 的底线。月均净增改用近 12 个月月度净增的中位数（现有 computeMonthlyGrowth 是首尾两点相减，一笔年终奖就能把预测拉飞）。四种降级：

历史不足（< 6 个完整月）→ 只显示进度条，「再记录 X 个月就能估算达成时间」
增速 ≤ 0 → 不显示日期，「按最近的变化，暂时还在远离这个目标」，绝不给假期望
波动过大（最大单月 > 3× 中位数）→ 照常给日期，但加一行「你的月度变化波动较大，这个时间仅作粗略参考」
已达成 → 卡片转为达成态，引导设定下一个目标
6两处预测必须共用一个估算器

里程碑「当前关」现在也显示预计月份。若只改目标卡，同一屏上两个预测口径会打架，用户一眼看得出矛盾。所以把增速估算收口成 services/goal.js 的单一函数，目标卡与里程碑都调它。这正是不变量 4 说的那类重复实现陷阱——这次不要再制造一份。

7与盘点闭环（见 ④ 号机）

盘点完成页在净值卡下方新增一行目标进度：名称 + 完成度 + 迷你进度条 + 「还差 X · 预计 Y 达成」，点击进入净值目标页。这是这个功能存在的最大理由——盘点是付出，看着目标更近一点是回报，留存循环由此闭合。未设目标时这一行显示为引导：「设一个目标，让每次盘点都有奔头 →」。

8你需要先做的一件事

goals 是新集合，要在云开发控制台建好，权限设为「仅创建者可读写」（与 accounts 一致，靠 _openid 天然隔离）。这一步不做，第 2 步之后的代码跑不起来。字段：name / targetFen / currency / createdAt / achievedAt / isArchived。

9交付顺序

① 增速估算收口 + 换成中位数算法（里程碑页先受益，用户可感知「预测变稳了」）→ ② goals 集合 + services/goal.js + 目标 CRUD → ③ 里程碑页改造为「净值目标」→ ④ 盘点完成页目标行。发布时 APP_VERSION → V2.1，releases.js 加条目，toolBadges.js 把 milestones 打上红点。
