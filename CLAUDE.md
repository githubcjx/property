# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

微信小程序「净值本」— a personal net-worth tracker. Native WeChat Mini Program (no React/Taro), using the `glass-easel` component framework. The backend is entirely **WeChat Cloud Development (云开发 / `wx.cloud`)** — there is no custom server. UI strings and code comments are in Chinese.

## Build / run / deploy

There is **no npm build, lint, or test tooling for the mini program** (`nodeModules: false` in `project.config.json`). All development happens inside **微信开发者工具 (WeChat DevTools)**:

- **Run/preview**: open the project root in WeChat DevTools and click 编译 (Compile). See `README.md` for first-time setup (importing the project, opening 云开发, creating the `accounts`/`transactions` collections and their indexes).
- **Cloud env ID** lives at the top of `miniprogram/app.js` (`CLOUD_ENV_ID`) — already set to a real environment; not a placeholder.
- **Cloud functions** live in `cloudfunctions/` and each has its own npm deps: `cd cloudfunctions/<fn> && npm install`. Currently only `fxRateSync/` (每日汇率抓取，见「多货币」不变量 / `services/fxRate.js`). Deploy via DevTools → 云开发 → right-click the function → 上传并部署. They are **not** part of the mini-program runtime — see each function's own `README.md`. Any secrets come from cloud-function env vars, never hardcoded. Crons in `config.json` are in **UTC** (北京时间 − 8h).

## Git workflow

**Always develop new features on a branch cut from `main` — never commit feature work directly to `main`.** (Hard requirement from the repo owner.)

1. `git checkout main && git pull`
2. `git checkout -b feat/<name>` and do all the work there
3. After the owner confirms, merge back into `main` (fast-forward when possible) and push
4. Do **not** delete feature branches unless explicitly asked — keep them around.

**The displayed version number has a single source of truth: `utils/version.js` (`APP_VERSION`, format `Vx.y.z`).** Home/settings/about/changelog pages all import it — never hardcode a version string in a page again. Bump it there (and only there) for every release; patches/bugfixes increment the `.z` (e.g. `V1.6` → `V1.6.1`). The `version` strings *inside* the changelog `releases` array are historical per-release labels and stay as-is.

**When a user-facing feature is finished, also update the in-app 更新日志 (changelog) — this is part of "done", not optional.** Edit the `releases` array in `pages/changelog/changelog.js` (newest first): either add a Chinese, user-facing bullet to the current unreleased version's `items`, or, for a new release, prepend a new `{ version, date: 'YYYY-MM', title, items: [...] }` block and bump `APP_VERSION` in `utils/version.js` to match. Write entries from the user's perspective (what they can now do), not in terms of files/functions. Skip only for pure refactors/docs/chores with no user-visible change.

Remote: `origin` = https://github.com/githubcjx/property.git. On Windows the editing tools may write CRLF; git's autocrlf normalizes to LF on commit. Write source files as **UTF-8 without BOM** — WeChat's WXSS compiler rejects a leading BOM (`unexpected ` at pos 1).

## Architecture & invariants

These are the cross-cutting rules that aren't obvious from any single file. Violating them silently corrupts financial data, so keep them consistent across the whole codebase.

**1. Money is integer 分 (cents), everywhere.** `balance`, `amount`, `balanceAfter` are always integer fen in the DB, in services, and in page logic. Convert to yuan **only** at the UI boundary via `miniprogram/utils/format.js` (`fenToYuan` / `yuanToFen` / `formatYuan` / `formatCNY` / `formatDelta`). Never do `/100` or `* 100` ad hoc.

**2. All DB access goes through the services layer.** `miniprogram/services/cloud.js` is the single accessor for the DB handle, command, the two collections, and `serverDate()`. Every other service requires it; pages call services, **never** `wx.cloud.database()` directly. Two collections, both user-isolated by `_openid` (auto): `accounts` and `transactions`. Deletion of accounts is **soft** (`isHidden: true`).

**3. Balance changes always write an account update *and* append a transaction.** `account.js` `setBalance`/`deltaBalance` update `accounts.balance` and append a `transactions` doc (`type: 'set'|'delta'`, with the post-change `balanceAfter` snapshot). When a transaction is later edited/deleted (`transaction.js`), the linked account's balance is adjusted by the diff, but **other historical transactions' `balanceAfter` are frozen snapshots and are deliberately not recomputed.**

**4. Net-worth math is duplicated by design — keep all copies in sync.** The rule (assets `liquid`/`investment`/`fixed`/`receivable` add, `debt` subtracts, and **only accounts with `includeInChart !== false` count**) is re-implemented in `index.js`, `stats.js`, `chart.js`, `health.js`, `milestones.js`, `benchmark.js`, `allocation.js` (资产配置环图), and `attribution.js` (净值变动归因). The canonical debt test is `isDebtCategory()` from `utils/categories.js`. If you change the rule, change it in all of them.

**5. Time-series = balance snapshots, current point = live balance.** `chart.js`, `stats.js`, and `milestones.js` reconstruct historical net worth by taking, for each time node, each account's most-recent `transaction.balanceAfter` at-or-before that node. The latest/"current" node instead reads the live `account.balance` (authoritative) so charts agree with the home screen. Cloud DB returns dates in several shapes (`Date` / number / string / `{$date}`); each service has a `toMs`/`toDate` helper to normalize — reuse that pattern, don't assume `Date`.

**6. Categories are the domain model.** `utils/categories.js` `CATEGORIES` is the source of truth: 5 fixed top categories, each with subTypes. Account `icon` is an **icon-key string** (e.g. `cash`, `house`) mapped to a `.ic-<key>` CSS class in `app.wxss` — not an emoji. `isIconKey()` distinguishes new icon-key data from legacy emoji strings; fall back to `folder` when unknown.

**7. Cross-page state via `getApp().globalData`.** Privacy toggle `hideAmount` (persisted to storage, hides all amounts as `****`), plus `reduceMotion`, `cloudReady`, and `theme` (persisted as `pref_theme`). Pages re-read these in `onShow` to stay in sync. Toggle through `app.toggleHideAmount()` / `app.setReduceMotion()` / `app.setTheme()`, not by mutating globalData directly.

**8. The trend chart is a subpackage.** `subpackages/chart-pkg/` bundles ECharts (~1MB) under `ec-canvas/` and is preloaded after the home page (`preloadRule` in `app.json`). If `ec-canvas/echarts.js` is missing in a fresh checkout, see the README's offline section.

**9. Theming = CSS variables, cascaded from the page root.** Base palette is defined on the `page` selector in `app.wxss` (`--accent`, `--accent-rgb`, `--liquid`/`--investment`/`--fixed`/`--receivable` + their `-rgb`, `--bg-*`, `--ink-*`, `--neb-*`). Each theme is a `.theme-<key>` class in `app.wxss` overriding those vars; every page binds `theme-{{theme}}` on **both** `.canvas-bg` and the `.page` root so the override cascades to all descendants (components included). `--debt`/`--neg` stay red across all themes (financial "negative" semantics). **Never hardcode accent/category hex or rgb in styles — always use `var(--…)`** so themes work. `utils/theme.js` is the single source of truth for the theme list (`THEMES`: key/name/`dots` swatches/`accent`/`investment`) and JS-side accent colors; ECharts line colors in `chart.js` read from it because canvas colors can't use CSS vars (keep the wxss vars and `theme.js` values in sync). Themes carry a `series` key and are grouped for the picker via `THEME_SERIES` (display order + section headers) and the derived `THEME_GROUPS`; series are 人民币纸币配色 (`banknote`, keys `yuan1`/…/`yuan100`), 经典深色 (`classic`), and 解锁质感 (`premium`, keys `slate`/`brutalist`). Some themes are **structural**, not just palette swaps: `.theme-slate` (软光浮雕) and `.theme-brutalist` (浅色粗野) also restyle shared surfaces (`.glass`/`.card`/`.cat-card`/buttons/FAB/tools panel…) inside their scope — all overrides stay confined to the `.theme-<key>` selector so other themes are untouched. Adding a theme = a `.theme-<key>` block in `app.wxss` **and** an entry in `THEMES` with a matching `series` (+ a `CAT_HEX` row so canvas/native components get the category colors). The picker is `pages/theme`; tapping a swatch calls `app.setTheme()` and reskins live. (The top-level untracked `theme/` dir holds banknote reference PNGs, not runtime assets.)

**Ad-locked themes.** A theme with `locked: true` in `THEMES` (currently `slate` + `brutalist`, the `premium`/质感臻选 series) *can* require watching a rewarded video before it's applied — but only when the master switch `THEME_LOCK_ENABLED` in `utils/theme.js` is `true`. It's currently **`false`** (UV below the 流量主 threshold, so both themes ship free): `isLocked()` short-circuits to `false`, so every theme is unlocked, `onPick` applies directly, and the picker hides the 「看广告解锁」 badge (theme page passes `lockEnabled` to the wxml). Flip it to `true` (and fill `THEME_AD_UNIT_ID`) to turn the gating on — no other code changes needed. When enabled: `isLocked(key)` in `utils/theme.js` reports whether a theme needs unlocking; unlock state is persisted app-side: `getApp().globalData.unlockedThemes` (storage `pref_unlocked_themes`), read via `app.isThemeUnlocked(key)` and written by `app.unlockTheme(key)` (idempotent, permanent). `app.onLaunch` grandfathers the *current* theme in (老用户 who set a now-locked theme while it was free aren't kicked out). The picker (`pages/theme`) intercepts `onPick` for locked-and-not-unlocked themes: it shows `wx.createRewardedVideoAd({ adUnitId: THEME_AD_UNIT_ID })` and only unlocks+applies on `onClose` with `res.isEnded`. `THEME_AD_UNIT_ID` is a **placeholder** (`adunit-0000…`) until the owner pastes a real 流量主 ad-unit id; while `isAdConfigured()` is false the picker falls back to a `wx.showModal` "模拟解锁" so the flow is testable in DevTools (which can't serve real ads anyway). Each locked theme unlocks independently (one rewarded view per theme). The swatch shows a 「看广告解锁」 badge (`.sw-lock`) until unlocked.

**Light themes need JS-side chrome sync.** `--bg-*`/nav-bar/pull-refresh colors are baked dark in `app.json` for the launch frame and can't follow the theme class. A theme marked `light: true` in `THEMES` (currently only `brutalist`) is collected into `LIGHT_THEMES` / `isLight(key)` in `utils/theme.js`; `app.applyThemeChrome()` reads it and calls `wx.setNavigationBarColor` / `setBackgroundColor` / `setBackgroundTextStyle` to swap the status-bar/bounce/loading colors to paper tones. It runs on `setTheme()` **and** in every page's `onShow` (add-account uses `onLoad`) — because those system colors reset when navigating between pages. When adding a page, call `app.applyThemeChrome()` in its `onShow`. For light themes, `catHex('debt')` returns a darker red (`DEBT_HEX_LIGHT`) since the default light-red is unreadable on paper, and ECharts colors in `chart.js` branch on `isLight` (axis/legend ink, debt line) with an optional per-theme `chartAccent`/`chartAccentRgb` override (brutalist swaps its pale signal-yellow line for blue).

**10. Data honesty — only show data the app actually stores or can compute; never fabricate.** Applies to shipped features **and** `prototypes/` mockups. Every number on screen must trace to stored data (`accounts`/`transactions`) or a real derivation from it — if it can't, change the design, don't invent the metric. Known traps: the 同龄对标 age distribution in `benchmark.js` is **placeholder** (`isPlaceholder: true`) — never present it as real, and don't build shareable "超过 X% 同龄人" content on it. The health score is **computed on the fly** (`health.js`, not persisted); month-over-month / historical scores are **recomputed** from `balanceAfter` snapshots via `health.evaluateAt(accounts, dateMs)` (same snapshot reconstruction as `stats.js`/invariant 5), never stored — and it returns `null` when there's no comparable history so the caller hides the delta instead of faking one. When you draw a prototype page, do not put a chart/stat/badge on it that the current data model can't produce. The 购买力/真实净值 feature (`services/realworth.js`) adjusts past net worth for inflation using **real** 国家统计局 CPI bundled in `utils/cpiData.js` (a chained price-level index; every 12-month ratio matches official 同比 exactly) — when the CPI series doesn't cover the window or there's no 12-month baseline it returns `coverage:'noCpi'|'short'` and the card degrades to nominal-only, never a fabricated inflation number. Keep `cpiData.js` the single JS source of truth; update it monthly from NBS (later a `cpiSync` cloud function will auto-refresh a `cpiSeries` collection, mirroring `fxRateSync`).

## Pages

`pages/`: `index` (home — net worth + category groups + a 工具/tools panel), `add-account`, `account-detail`, `transaction-detail`, `settings`, `theme` (主题切换选择页), `about`, `changelog` (更新日志), `health` (财务体检, scoring in `services/health.js`), `milestones` (里程碑, `services/milestones.js`), `insights` (资产洞察 — 购买力/真实净值 `services/realworth.js` + 资产配置分析 `services/allocation.js` + 净值变动归因 `services/attribution.js`), `peer-benchmark` (同龄对标, `services/benchmark.js`; entry currently offline on home). The trend chart is `subpackages/chart-pkg/pages/chart`. Reusable components live in `components/` (`amount-input`, `account-card`, `category-header`, `share-sheet`). `share-sheet` is the「晒成绩」分享面板: a page passes a `card` object (score/status/chips/`netWorthFen`/tagline), the component renders a DOM preview + 金额打码 toggle (**default masked**), draws a poster to an offscreen `canvas type="2d"`, and emits `bind:posterready` with the temp image path; the host page returns that path as `imageUrl` in `onShareAppMessage`/`onShareTimeline` so WeChat never screenshots raw numbers. 分享卡只含相对量（分数/等级/标签），绝不含绝对金额或同龄对标占位数据。
