# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

微信小程序「净值本」— a personal net-worth tracker. Native WeChat Mini Program (no React/Taro), using the `glass-easel` component framework. The backend is entirely **WeChat Cloud Development (云开发 / `wx.cloud`)** — there is no custom server. UI strings and code comments are in Chinese.

## Build / run / deploy

There is **no npm build, lint, or test tooling for the mini program** (`nodeModules: false` in `project.config.json`). All development happens inside **微信开发者工具 (WeChat DevTools)**:

- **Run/preview**: open the project root in WeChat DevTools and click 编译 (Compile). See `README.md` for first-time setup (importing the project, opening 云开发, creating the `accounts`/`transactions` collections and their indexes).
- **Cloud env ID** lives at the top of `miniprogram/app.js` (`CLOUD_ENV_ID`) — already set to a real environment; not a placeholder.
- **Cloud functions** live in `cloudfunctions/` and each has its own npm deps: `cd cloudfunctions/<fn> && npm install`. Currently `fxRateSync/` (每日汇率抓取，见「多货币」不变量 / `services/fxRate.js`) and `inventoryRemind/` (每月 1 日下发盘点提醒订阅消息). Deploy via DevTools → 云开发 → right-click the function → 上传并部署. They are **not** part of the mini-program runtime — see each function's own `README.md`. Any secrets come from cloud-function env vars, never hardcoded. Crons in `config.json` are in **UTC** (北京时间 − 8h).

## Git workflow

**Always develop new features on a branch cut from `main` — never commit feature work directly to `main`.** (Hard requirement from the repo owner.)

1. `git checkout main && git pull`
2. `git checkout -b feat/<name>` and do all the work there
3. After the owner confirms, merge back into `main` (fast-forward when possible) and push
4. Do **not** delete feature branches unless explicitly asked — keep them around.

**The displayed version number has a single source of truth: `utils/version.js` (`APP_VERSION`, format `Vx.y.z`).** Home/settings/about/changelog pages all import it — never hardcode a version string in a page again. Bump it there (and only there) for every release; patches/bugfixes increment the `.z` (e.g. `V1.6` → `V1.6.1`). The `version` strings *inside* the changelog `releases` array are historical per-release labels and stay as-is.

**When a user-facing feature is finished, also update the in-app 更新日志 (changelog) — this is part of "done", not optional.** Edit the `releases` array in **`utils/releases.js`** (single source; both `pages/changelog` and the home-page update popup read it), newest first: either add a Chinese, user-facing bullet to the current unreleased version's `items`, or, for a new release, prepend a new `{ version, date: 'YYYY-MM', title, items: [...] }` block and bump `APP_VERSION` in `utils/version.js` to match. Skip only for pure refactors/docs/chores with no user-visible change.

**Changelog entries must be short and plain — this is a hard requirement from the repo owner.** One line per item, ideally under ~25 Chinese characters, and never more than 4–5 items per release. Say what the user can now do, in their words. Do **not** explain how it works, name algorithms/files/functions, or stack multiple clauses onto one bullet with `；`. Compress instead of enumerating: several related changes become one bullet, and implementation detail is simply dropped — users do not care that a median replaced an endpoint difference. Write it, then cut it in half.
> Good: `新增「一键盘点」：逐个核对账户余额，几分钟全部更新完`
> Bad: `新增「一键盘点」：逐个核对各账户余额，一致就点确认，不一致顺手改掉，几分钟让全部数据回到最新`

Remote: `origin` = https://github.com/githubcjx/property.git. On Windows the editing tools may write CRLF; git's autocrlf normalizes to LF on commit. Write source files as **UTF-8 without BOM** — WeChat's WXSS compiler rejects a leading BOM (`unexpected ` at pos 1). **The one place a BOM is required is the opposite direction: CSV files produced by `services/export.js` must start with `\uFEFF`**, or Excel on a Chinese Windows opens them as GBK mojibake. Don't "fix" that BOM away; it is written as the escape `'\uFEFF'` (never a literal zero-width char) precisely so it stays visible in the source.

## Architecture & invariants

These are the cross-cutting rules that aren't obvious from any single file. Violating them silently corrupts financial data, so keep them consistent across the whole codebase.

**1. Money is integer 分 (cents), everywhere.** `balance`, `amount`, `balanceAfter` are always integer fen in the DB, in services, and in page logic. Convert to the display unit **only** at the UI boundary via `miniprogram/utils/format.js`. Never do `/100` or `* 100` ad hoc.

**Always use the currency-aware pair `formatMoney(fen, ccy, { symbol: true })` / `fenToUnit` / `unitToFen`, and never hand-build an amount by concatenating a symbol** (`'¥' + formatYuan(...)`, `'¥' + n`, a literal `¥` in WXML next to a number). Two things break otherwise: a 外币 account renders its own balance with the wrong symbol, and `/100` is simply wrong for 0-decimal currencies like JPY — `yuanToFen` on a JPY amount inflates it 100×, which corrupts stored data, not just the display. The legacy CNY-only helpers (`fenToYuan` / `yuanToFen` / `formatYuan` / `formatCNY` / `formatDelta`) remain only for values that are 人民币 by definition; do not use them for anything that carries an account's `currency`. Amounts that are internally 人民币 (net worth, category totals, chart series, 增速) must go through `cnyToBaseFen()` + the 本位币 symbol before display — see `utils/networth.js`. The one deliberate exception is `milestones.js` `fmtAmountText`: the 7 关口 are 人民币 anchors (「一百万」is a CNY expression; showing `$14 万` would destroy the 高光关口), and it is commented as such.

**2. All DB access goes through the services layer.** `miniprogram/services/cloud.js` is the single accessor for the DB handle, command, the two collections, and `serverDate()`. Every other service requires it; pages call services, **never** `wx.cloud.database()` directly. Four collections, all user-isolated by `_openid` (auto): `accounts`, `transactions`, `goals` (净值目标; one active row at a time — switching goals archives the old one via `isArchived`, never deletes), and `reminders` (盘点提醒订阅, one row per user). Plus two written only by cloud functions: `fxRates` (public read) and `remindLogs`. Deletion of accounts is **soft** (`isHidden: true`).

**3. Balance changes always write an account update *and* append a transaction.** `account.js` `setBalance`/`deltaBalance` update `accounts.balance` and append a `transactions` doc (`type: 'set'|'delta'`, with the post-change `balanceAfter` snapshot). When a transaction is later edited/deleted (`transaction.js`), the linked account's balance is adjusted by the diff, but **other historical transactions' `balanceAfter` are frozen snapshots and are deliberately not recomputed.** The converse also holds: **a confirmation that the balance did *not* change must not write a transaction.** 一键盘点's 「一致，确认」 calls `account.js` `touchChecked()`, which only stamps `checkedAt` — inventing a zero-amount transaction would pollute the ledger and every `balanceAfter`-based reconstruction. `checkedAt` = "余额最后一次被人核对的时间"; it is also stamped by `setBalance`/`deltaBalance`. Read it via `services/inventory.js` `freshnessMs()` (`checkedAt` → `updatedAt` → `createdAt`), **never `updatedAt` alone** — renaming an account or editing its note bumps `updatedAt` too and would overstate freshness.

**4. Net-worth math is duplicated by design — keep all copies in sync.** The rule (assets `liquid`/`investment`/`fixed`/`receivable` add, `debt` subtracts, and **only accounts with `includeInChart !== false` count**) is re-implemented in `index.js`, `stats.js`, `chart.js`, `milestones.js`, `inventory.js`, `allocation.js` (资产配置环图), and `report.js` (月度小结的净值涨幅与归因). The canonical debt test is `isDebtCategory()` from `utils/categories.js`. If you change the rule, change it in all of them.

**4b. 增速估算 is the opposite — exactly one implementation, never duplicate it.** `utils/growth.js` `estimateMonthlyGrowth(timeline)` is the single source for "月均净增": the median of the last 12 complete calendar months' month-over-month deltas, returning `{ monthlyFen, coverage, months, volatile }`. Both 「净值目标」's ETA and 里程碑's 当前关预计月份 read it, and they **must** — two estimators would put two contradicting predictions on the same screen. It is a median (not an endpoint difference) on purpose: one 年终奖 inflates an endpoint-based rate ~5×. **A calendar month with no recorded transaction contributes no sample** — "没有记录" ≠ "没有变化", and treating empty months as 0 poisons the median: a real user who updated twice a year had 7 empty months out of 12, median collapsed to 0, and the card claimed 「你在远离这个目标」 while net worth had actually grown 20 万. A month that *was* recorded and genuinely didn't move still contributes a real 0. `coverage` drives honest degradation (`short` = fewer than 6 **recorded** complete months, `nonPositive` = median ≤ 0); callers hide the date rather than fake one (invariant 10). If you need a growth number anywhere new, call this function — do not write another one.

**5. Time-series = balance snapshots, current point = live balance.** `chart.js`, `stats.js`, and `milestones.js` reconstruct historical net worth by taking, for each time node, each account's most-recent `transaction.balanceAfter` at-or-before that node. The latest/"current" node instead reads the live `account.balance` (authoritative) so charts agree with the home screen. Cloud DB returns dates in several shapes (`Date` / number / string / `{$date}`); each service has a `toMs`/`toDate` helper to normalize — reuse that pattern, don't assume `Date`.

**6. Categories are the domain model.** `utils/categories.js` `CATEGORIES` is the source of truth: 5 fixed top categories, each with subTypes. Account `icon` is an **icon-key string** (e.g. `cash`, `house`) mapped to a `.ic-<key>` CSS class in `app.wxss` — not an emoji. `isIconKey()` distinguishes new icon-key data from legacy emoji strings; fall back to `folder` when unknown.

**7. Cross-page state via `getApp().globalData`.** Privacy toggle `hideAmount` (persisted to storage, hides all amounts as `****`), plus `reduceMotion`, `cloudReady`, and `theme` (persisted as `pref_theme`). Pages re-read these in `onShow` to stay in sync. Toggle through `app.toggleHideAmount()` / `app.setReduceMotion()` / `app.setTheme()`, not by mutating globalData directly.

**8. The trend chart is a subpackage.** `subpackages/chart-pkg/` bundles ECharts (~1MB) under `ec-canvas/` and is preloaded after the home page (`preloadRule` in `app.json`). If `ec-canvas/echarts.js` is missing in a fresh checkout, see the README's offline section.

**9. Theming = CSS variables, cascaded from the page root.** Base palette is defined on the `page` selector in `app.wxss` (`--accent`, `--accent-rgb`, `--liquid`/`--investment`/`--fixed`/`--receivable` + their `-rgb`, `--bg-*`, `--ink-*`, `--neb-*`). Each theme is a `.theme-<key>` class in `app.wxss` overriding those vars; every page binds `theme-{{theme}}` on **both** `.canvas-bg` and the `.page` root so the override cascades to all descendants (components included). `--debt`/`--neg` stay red across all themes (financial "negative" semantics). **Never hardcode accent/category hex or rgb in styles — always use `var(--…)`** so themes work. `utils/theme.js` is the single source of truth for the theme list (`THEMES`: key/name/`desc`/`dots` swatches/`accent`/`investment`) and JS-side accent colors; ECharts line colors in `chart.js` read from it because canvas colors can't use CSS vars (keep the wxss vars and `theme.js` values in sync). **V3.0 cut the list from 14 themes to 2** — `slate` (晴空软光, default, dark) and `brutalist` (硬核粗野, light). Both are **structural** themes, not palette swaps: they also restyle shared surfaces (`.glass`/`.card`/`.cat-card`/buttons/FAB…) inside their scope, and all overrides stay confined to the `.theme-<key>` selector. The 12 deleted ones (人民币纸币 6 + 经典深色 6) were pure recolors — three places to maintain each, zero effect on any 盘点. Do not re-add a theme that is only a palette; the bar is "a different structural feel". Adding one = a `.theme-<key>` block in `app.wxss` **and** an entry in `THEMES` (+ a `CAT_HEX` row so canvas/native components get the category colors). The base palette on the `page` selector no longer belongs to any theme, but is still required — each theme only overrides the vars it cares about and falls back to that base. Stored `pref_theme` may name a deleted theme, so `app.onLaunch` runs it through `normalizeTheme()` and re-persists (without it, CSS falls back to the base palette while `CAT_HEX` falls back to the default theme — canvas and stylesheet disagree). The picker is `pages/theme`; tapping a swatch calls `app.setTheme()` and reskins live. (The top-level untracked `theme/` dir holds banknote reference PNGs, not runtime assets.)

**No ad-locked themes.** V3.0 deleted the whole 「看广告解锁主题」 scaffolding (`THEME_LOCK_ENABLED` / `isLocked` / `THEME_AD_UNIT_ID` / `isAdConfigured` / `app.unlockedThemes` / `app.isThemeUnlocked` / `app.unlockTheme` / the `.sw-lock` badge). With only two themes left, gating them means gating all of them — that switch could only ever be a landmine. Every theme is free and applies on tap. If 流量主 monetization happens later, design it from scratch; do not resurrect this. (The same 「未配置就整条链路 no-op」 pattern still lives in `utils/reminder.js` for the 订阅消息 template id — different thing, stays.)

**Light themes need JS-side chrome sync.** `--bg-*`/nav-bar/pull-refresh colors are baked dark in `app.json` for the launch frame and can't follow the theme class. A theme marked `light: true` in `THEMES` (currently only `brutalist`) is collected into `LIGHT_THEMES` / `isLight(key)` in `utils/theme.js`; `app.applyThemeChrome()` reads it and calls `wx.setNavigationBarColor` / `setBackgroundColor` / `setBackgroundTextStyle` to swap the status-bar/bounce/loading colors to paper tones. It runs on `setTheme()` **and** in every page's `onShow` (add-account uses `onLoad`) — because those system colors reset when navigating between pages. When adding a page, call `app.applyThemeChrome()` in its `onShow`. For light themes, `catHex('debt')` returns a darker red (`DEBT_HEX_LIGHT`) since the default light-red is unreadable on paper, and ECharts colors in `chart.js` branch on `isLight` (axis/legend ink, debt line) with an optional per-theme `chartAccent`/`chartAccentRgb` override (brutalist swaps its pale signal-yellow line for blue).

**9b. 盘点提醒 needs two constants filled before it does anything.** 微信「一次性订阅」grants exactly one send per user consent, so the loop is 盘点完成 → 订阅 → 次月 1 日提醒 → 再盘点; the completion page re-asks every time on purpose. `TEMPLATE_ID` must be filled **in both** `utils/reminder.js` (client) and `cloudfunctions/inventoryRemind/index.js` — while either is empty that side no-ops (client shows 「即将上线」 and never calls the API, cloud function returns `skipped`), mirroring the `THEME_AD_UNIT_ID` / `isAdConfigured()` pattern. The template's field names (`thing1`/`time2`/…) differ per template and must match `buildData()` or WeChat returns 47003. `reminders.pending` is the "has an unused grant" flag; the cloud function clears it **whether or not the send succeeded**, because the quota is consumed on call — see that function's README.

**10. Data honesty — only show data the app actually stores or can compute; never fabricate.** Applies to shipped features **and** `prototypes/` mockups. Every number on screen must trace to stored data (`accounts`/`transactions`) or a real derivation from it — if it can't, change the design, don't invent the metric. Known traps: 同龄对标 was **deleted in V2.0** precisely for this reason — its age distribution was hardcoded placeholder data that read like a real statistic. Do not reintroduce it (or any "超过 X% 同龄人" content) without a real, citable data source. (The 财务体检 health-score feature was **deleted in the V2.1 "更纯粹" pass** — nobody used it, and its ratios/score overlapped 资产配置; do not reintroduce a persisted or standalone health score.) When you draw a prototype page, do not put a chart/stat/badge on it that the current data model can't produce. The 购买力/真实净值 concept adjusts past net worth for inflation using **real** 国家统计局 CPI bundled in `utils/cpiData.js` (a chained price-level index; every 12-month ratio matches official 同比 exactly), and now lives **solely** in the trend chart's 名义/真实 toggle: `chart.js` `getChartSeries` returns a parallel `seriesReal` (each node scaled by `factorBetween(nodeMs, now)`, right edge = today so real·nominal converge there) plus `realCoverage` (false when the range predates CPI data → page shows a note, those nodes stay nominal). Keep `cpiData.js` the single JS source of truth; update it monthly from NBS (later a `cpiSync` cloud function will auto-refresh a `cpiSeries` collection, mirroring `fxRateSync`).

## Pages

`pages/`: `index` (home — net worth + category groups + 盘点入口 + a single 「回顾」 door), `add-account`, `account-detail`, `transaction-detail`, `settings`, `theme` (主题切换选择页), `about`, `changelog` (更新日志), `inventory` (一键盘点, `services/inventory.js`), `milestones` (**净值目标** — 顶部「我的目标」`services/goal.js` + 下方 7 关里程碑 `services/milestones.js`; 路由名仍是 milestones), `insights` (**资产配置** — 环图 + 关键比率 + 集中度, `services/allocation.js`; 路由名仍是 insights). 净值变动归因现只在 `report`（月度小结）里，购买力/真实只在趋势图的名义/真实切换里.

**V3.0 · 一扇门 + 回顾中枢.** The home page used to open a 工具 bottom-sheet with four side-by-side lenses (趋势 / 资产配置 / 净值目标 / 月度小结). Four doors into one room — 「我这段时间过得怎么样」. Now the home FAB is a single 「回顾」 that navigates straight to the trend chart (`subpackages/chart-pkg/pages/chart`), and **that page is the hub**: the curve stays the one protagonist, and below it sit three read-only summary blocks — 资产构成 (small conic ring + top-4 legend, from `allocation.evaluate`), 目标进度 (bar + 还差多少, from `goal.buildGoalView` with `null` growth — the ETA needs sampling and stays on the goal page), and 上月小结 (a one-row entry). `insights` / `milestones` / `report` survive **as detail pages reachable only from the hub** (plus the month-start banner for `report`); do not add a second door to them from the home screen. The hub recomputes nothing — every block calls an existing service and degrades silently (hides itself) if that call fails, so a broken goal never takes the chart down with it. `utils/toolBadges.js` and the `tool_badge_seen` storage were deleted along with the drawer. **A 二级页's back/close button must call `goBack()` from `utils/nav.js`, never `wx.navigateBack()` directly** — 订阅消息落地、分享卡、小程序码 all drop the user straight onto a 二级页 with a one-entry page stack, where `navigateBack` silently no-ops and the user is stuck; `goBack()` falls back to `reLaunch` 首页. Reusable components live in `components/` (`amount-input`, `share-sheet`) — the home page renders its category/account rows inline, not via components. `share-sheet` is the「晒成绩」分享面板: a page passes a `card` object (score/status/chips/`netWorthFen`/tagline), the component renders a DOM preview + 金额打码 toggle (**default masked**), draws a poster to an offscreen `canvas type="2d"`, and emits `bind:posterready` with the temp image path; the host page returns that path as `imageUrl` in `onShareAppMessage`/`onShareTimeline` so WeChat never screenshots raw numbers. 分享卡只含相对量（分数/等级/标签），绝不含绝对金额。
